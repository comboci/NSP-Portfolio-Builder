# مرورگرمحور کردن توسعه — NSP Portfolio Builder V138

تا پایان بازطراحی، مبنای کار فایل `index.html` است که با Edge/Chrome اجرا می‌شود و اطلاعاتش را در IndexedDB مرورگر ذخیره می‌کند. به Tauri و SQLite برای این مرحله نیازی نیست. سورس Rust/SQLite و Migrationهای 001 تا 013 پاک یا بازنویسی نمی‌شوند؛ اتصال و تطبیق آن‌ها به مرحله بعد موکول است. داده‌های مرورگر و SQLite مستقل‌اند و انتقال خودکار بینشان تضمین نمی‌شود؛ پیش از جابه‌جایی محیط باید JSON Export/Import و بازیابی را بررسی کرد.

برای کار روی GitHub، در آغاز یک نسخه از `index.html` و Project Evolution گرفته و روی یک نسخه ثابت ویرایش می‌شود. بعد از پایان تغییرات HEAD مجدداً بررسی و یک Commit با پیشوند فارسی `pro-` روی main ثبت می‌شود؛ از بازنویسی Commit دیگران جلوگیری می‌کنیم. زمان‌بندی ساعتی Project Evolution هنگام این مرحله غیرفعال بررسی شد.

اصلاحات V138: عدم حذف آخرین گروه قالب؛ رد نام تکراری در تغییر نام گروه؛ تأیید نام پورتفولیو و صفحه پیش از اعمال قالب از کتابخانه؛ بازگردانی تغییرات در حافظه وقتی ذخیره حتی آغاز نشود؛ حفظ پیش‌نویس همراه هشدار صریح زمانی که نتیجه ذخیره ناهمگام نامعلوم است. این اصلاحات فقط بخشی از TASK-076 هستند و به معنی حل کامل سازگاری، اتمیک‌بودن یا بازنشستگی Master/Section نیستند.

طبق DEC-006 هیچ Build، Test، Static Checker یا Runtime اجرا نشده، و هیچ دیتابیس، پروژه یا فایل تصویری پاک نشده است. بررسی صفحه‌سازی، قالب، کامپوننت، IndexedDB و PDF با مالک انجام می‌شود.
